# 原始调用方式归档

本文档归档 `tupian-shengcheng` 这个 skill 最初使用的调用方式、关键参数和核心代码片段，便于后续需要回退、兼容、对照或在别处复用时参考。

当前版本已经把这套原始调用代码正式写回 `scripts/generate_image.py`，对应 `request_mode = "old"` 或 `profile = "old"`。

## 原始默认配置

最初版本默认使用下面这组配置：

```json
{
  "base_url": "https://llm.devoi.net/v1/chat/completions",
  "model": "gemini-3-pro-image-preview",
  "api_key": "从 config.json 或环境变量读取"
}
```

原始环境变量名：

- `DEVOI_API_KEY`

## 原始调用方式

原始 skill 也是走 OpenAI 风格的 `chat/completions`，但当时假设更窄：

1. 请求发到 `chat/completions`
2. 提示词直接作为 `messages[0].content`
3. 默认使用流式返回
4. 接口最终会在文本里返回一个图片链接
5. 典型形式是 Markdown 图片链接，例如 `![](https://...)`

### 原始最小请求体

```json
{
  "model": "gemini-3-pro-image-preview",
  "messages": [
    {
      "role": "user",
      "content": "请生成一张信息图，主题是时间管理"
    }
  ],
  "stream": true
}
```

### 原始命令行调用

```bash
python scripts/generate_image.py --prompt "一张小红书风格的知识卡片：时间管理" --out "C:\temp\time.png"
```

### 原始覆盖方式

```bash
set DEVOI_API_KEY=sk-...
python scripts/generate_image.py --prompt "..."

python scripts/generate_image.py --prompt "..." --base-url "https://llm.devoi.net/v1/chat/completions" --model "gemini-3-pro-image-preview"
```

## 原始脚本关注的核心参数

| 参数 | 说明 |
|------|------|
| `--prompt` | 直接传入提示词 |
| `--prompt-file` | 从文件读取提示词 |
| `--base-url` | 指向旧版 `chat/completions` 地址 |
| `--model` | 旧版默认模型 `gemini-3-pro-image-preview` |
| `--api-key` | 可覆盖 `DEVOI_API_KEY` 或 `config.json` |
| `--out` | 输出文件或输出目录 |
| `--timeout` | 请求超时 |
| `--no-stream` | 不走流式 |

## 原始响应约定

最初版本主要假设接口会返回以下任一种文本：

1. Markdown 图片链接

```text
![](https://example.com/image.png)
```

2. 纯图片 URL

```text
https://example.com/image.png
```

3. `data:image/...;base64,...`

```text
data:image/png;base64,iVBORw0KGgoAAA...
```

原始版本最稳定的路径是第 1 种，也就是模型文本中直接嵌 Markdown 图片链接。

## 原始核心代码片段

下面这几段是原始 skill 的关键逻辑，保留的是当时的实现思路，而不是当前版本的完整代码。

### 1. 默认常量

```python
DEFAULT_BASE_URL = "https://llm.devoi.net/v1/chat/completions"
DEFAULT_MODEL = "gemini-3-pro-image-preview"
ENV_API_KEY = "DEVOI_API_KEY"
```

### 2. 从文本里提取图片链接

```python
def extract_image_url(text: str) -> str | None:
    if not text:
        return None
    m = re.search(r"!\[[^\]]*\]\(([^)]+)\)", text)
    if m:
        return m.group(1).strip()
    urls = re.findall(r"https?://\S+", text)
    for u in urls:
        if re.search(r"\.(png|jpe?g|webp)(\?|$)", u, re.IGNORECASE):
            return u.strip()
    return urls[0].strip() if urls else None
```

### 3. 解析流式返回

```python
def parse_streaming_response(resp) -> str:
    content = ""
    for line in resp.iter_lines(decode_unicode=True):
        if not line:
            continue
        if line.startswith("data:"):
            data = line[len("data:") :].strip()
            if data == "[DONE]":
                break
            try:
                obj = json.loads(data)
            except Exception:
                continue
            choices = obj.get("choices") or []
            if not choices:
                continue
            delta = choices[0].get("delta") or {}
            piece = delta.get("content")
            if piece:
                content += piece
    return content
```

### 4. 发送请求

```python
def request_image(base_url: str, api_key: str, model: str, prompt: str, stream: bool, timeout: int) -> str:
    headers = {
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json",
    }
    payload = {
        "model": model,
        "messages": [{"role": "user", "content": prompt}],
        "stream": stream,
    }
    resp = requests.post(base_url, headers=headers, json=payload, stream=stream, timeout=timeout)
    if resp.status_code != 200:
        raise RuntimeError(f"API error {resp.status_code}: {resp.text[:500]}")

    if stream:
        return parse_streaming_response(resp)

    data = resp.json()
    choices = data.get("choices") or []
    if not choices:
        return ""
    msg = choices[0].get("message") or {}
    return msg.get("content") or ""
```

当前脚本中的对应实现是独立的 `request_image_legacy(...)` 分支，调用时不会混入 flow2api 的兼容解析逻辑。

### 5. 下载图片

```python
def download_image(url: str, out_path: Path, timeout: int) -> None:
    if url.startswith("data:image/"):
        m = re.match(r"data:image/[^;]+;base64,(.*)", url, re.IGNORECASE | re.DOTALL)
        if not m:
            raise RuntimeError("Invalid data URI for image")
        data = base64.b64decode(m.group(1))
        out_path.parent.mkdir(parents=True, exist_ok=True)
        with open(out_path, "wb") as f:
            f.write(data)
        return

    resp = requests.get(url, stream=True, timeout=timeout)
    if resp.status_code != 200:
        raise RuntimeError(f"Image download failed {resp.status_code}: {url}")
    out_path.parent.mkdir(parents=True, exist_ok=True)
    with open(out_path, "wb") as f:
        for chunk in resp.iter_content(chunk_size=8192):
            if chunk:
                f.write(chunk)
```

## 与当前版本的关系

当前 `scripts/generate_image.py` 是对原始方式的扩展，不是替换掉原始思路：

- 旧方式仍然成立：`chat/completions` + 文本里给图片链接
- 当前版本只是额外兼容了图片二进制、JSON URL、`b64_json` 等返回
- 如果以后你明确要“按原来的方式调”，本质上就是：
  - 把 `base_url` 切回旧地址
  - 把 `model` 切回 `gemini-3-pro-image-preview`
  - 优先假设返回的是 Markdown 图片链接
